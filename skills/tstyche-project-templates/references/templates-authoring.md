# `// @tstyche template` and generation contracts

Use this file when authoring a `.tst.ts` whose default export is generated type-test source text, marked with `// @tstyche template` at the top. The live reference is https://tstyche.org/guides/template-test-files. The directive marks the file as a template; the generator's job is to produce type-test text that is valid for every supported input.

## Minimal template

```ts
// @tstyche template
function generate() {
  return `import { expect, test } from "tstyche";

test("smoke", () => {
  expect<string>().type.toBe<string>();
});
`;
}

export default generate();
```

The file's default export must be a string. Here, the file calls `generate()` before exporting its output; TSTyche imports that string as the type-test source.

## Determinism

- Templates must be deterministic. Same inputs, same output, byte-for-byte.
- Avoid `Date.now()`, `Math.random()`, `Object.keys` ordering, set iteration order, and locale-dependent formatting. Sort keys before emitting them.
- Pin inputs to the function's arguments. The template is a function of its arguments alone; environment, time, and filesystem state must not influence the output.
- When a generated name collides, the right answer is to dedupe at generation time, not at run time. Stable names are part of the contract.

## Stable test names

- Use argument values in the test name. `test(\`case: \${JSON.stringify(input)}\`, ...)` is robust; `test(\`case\`, ...)` is not.
- Cap the number of cases generated by a single template. Hundreds of generated cases slow the runner; thousands stall it.
- Group by feature, not by argument count. The matrix below shows what's in scope; the test name shows which point in the matrix is being exercised.

## Edge inputs

- Test the template against boundary inputs (`null`, `undefined`, `0`, `""`, `[]`, `{}`). The boundary cases are where templates usually break.
- Validate that the emitted source is valid TypeScript for every input. A template that emits text that fails to parse is the worst kind of failure — it looks like an assertion failure but is actually a generation bug.
- Validate that the emitted imports resolve. The template must always import from `tstyche`; arbitrary imports from the project can cause issues if the runner resolves them against the wrong TSConfig.
- Validate that the emitted assertions reference symbols that exist in the supported TypeScript and the package under test. Asserting on a missing type is indistinguishable from asserting a wrong type without careful reading of the message text.

## When a template is wrong surface

- Use a template when the matrix of similar cases is clearer than repeated handwritten tests. Three or four `.map(...)`-able cases is the threshold.
- Do not use a template when materially different expectations would need to be hidden in string concatenation. The hidden expectations cannot be discovered by code search and become maintenance debt.
- Do not use a template when the input to the generator depends on filesystem state, network, or runtime. Templates are pure functions of their arguments.

## Validation workflow

1. Generate the output by calling the function with at least three input shapes: a small input, the canonical input, and a boundary input.
2. For each generated output, save it to a temporary `.tst.ts` file and run `tstyche --target <each supported>` against it. Any failure here is a generation bug, not a test failure.
3. Add the generation function's unit tests to the host test suite. They run independently of TSTyche and catch regressions before the template reaches TSTyche.

## Common mistakes

- Marking a file `// @tstyche template` while also exporting assertions. The directive says the default export is generated text; mixing the two confuses the runner.
- Generating imports with incorrect relative paths or package specifiers. Check the emitted text from the generated file's location, then correct the specifier or the relevant module-resolution and path settings; `include` does not make an invalid import resolve.
- Forgetting the `tstyche` import inside the generated output. The emitted text is a complete file, not a fragment.
- Sorting by file-system order instead of by argument value. Use a stable sort key before emitting.
- Generating test names with `Symbol`s or non-idempotent expressions. The runner may execute the same template twice in different matrix slots; a stable key prevents cross-runner state pollution.
